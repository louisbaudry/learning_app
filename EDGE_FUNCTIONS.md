# Supabase Edge Functions

**Status:** 🚧 In Development  
**Date:** 2026-09-10  

Edge Functions are server-side TypeScript functions that run on Supabase infrastructure. They handle logic that:
- Must not run on the client (holds secrets like Claude API keys)
- Requires creating auth users (device linking)
- Needs atomic transactions across multiple database operations

---

## Architecture

### Why Edge Functions?

Per `SPECIFICATIONS.md` §11 Decision 2:
- **No standalone backend server** — only Supabase Edge Functions for secrets/auth
- **Row Level Security** enforces access control (RLS policies on all tables)
- **Client SDK** (web admin, mobile app) talks directly to Supabase for data

### When to Use Edge Functions vs. DB Functions

| Operation | Edge Function | DB Function (PL/pgSQL) | RLS Policy |
|---|---|---|---|
| **Answer validation** | No (use DB function) | ✅ `submit_answer()` | ✅ RLS on responses |
| **Device linking** | ✅ Redeem code, create auth user | Supporting role | ✅ RLS on student_devices |
| **Claude API calls** | ✅ Holds API key | — | — |
| **Image uploads** | ✅ Generate signed URLs | — | ✅ RLS on storage |
| **Data reads/writes** | No | — | ✅ RLS policies |

## Implemented Functions

### 1. `redeem-link-code` ✅ (Device Linking)

**Purpose:** Validate a one-time device link code and create an anonymous auth user for the child's phone.

**Request:**
```typescript
POST /functions/v1/redeem-link-code

{
  "code": "TIGRE-7342",        // One-time code generated by parent
  "device_name": "Samsung Galaxy A54"  // User's device name
}
```

**Response:**
```typescript
{
  "success": true,
  "student_id": "uuid...",     // Student this device is linked to
  "device_id": "uuid...",      // The student_devices record
  "auth_user_id": "uuid..."    // Anonymous auth user for this device
}
```

**Security:**
- Codes expire after 48 hours (parent sets this when generating)
- Each code can only be redeemed once
- Function runs with `service_role` key (bypasses RLS to create auth users)
- Students cannot see parent/family data (RLS policies enforce this)

**Flow:**
1. Parent generates code in admin panel
   - Admin panel calls DB function → creates `device_link_codes` row
2. Parent shows code to child
3. Child enters code in mobile app
4. Mobile app calls `redeem-link-code` Edge Function
5. Function validates code, creates anonymous auth user, links device
6. Mobile app uses returned `auth_user_id` for all future requests
7. RLS policies on `student_devices`, `assignments`, `responses` check `auth.uid() == auth_user_id`

**Reference:** `DATABASE_SCHEMA.md` §3.5–3.6, `SPECIFICATIONS.md` §11 Decision 7

## Planned Functions

### 2. `submit-answer` (Answer Validation)

**Status:** 🚧 Design phase

Currently implemented as a PostgreSQL `security_definer` function (`submit_answer()` in schema). This Edge Function wrapper is optional — it would:
- Allow mobile app to call HTTP endpoint instead of direct RPC
- Return structured JSON instead of raw DB results
- Handle response formatting

**Approach:** Use existing DB function, add Edge Function wrapper if needed.

### 3. `upload-image` (Signed URLs)

**Status:** 🚧 Design phase

**Purpose:** Generate time-limited signed URLs for image uploads/downloads.

**Security:**
- Parents upload images → stored in `question-images/` bucket
- Images grouped by `family_id/` prefix
- RLS on storage bucket ensures family isolation
- Edge Function validates family ownership before generating signed URL

**Flow:**
1. Admin panel calls `upload-image` with file info
2. Function validates parent's family access
3. Returns presigned upload URL (POST)
4. Parent uploads directly to Supabase Storage
5. Function returns download URL (presigned GET, time-limited)

### 4. `generate-lesson` (AI Content Generation)

**Status:** 🚧 Design phase — see `AI_CONTENT_GENERATION.md` for the full
design (request parameters, system prompt, structured-output contract,
model/A-B strategy, review workflow). Holds the only copy of
`ANTHROPIC_API_KEY`; everything else it does with the database should run
scoped to the calling parent's own JWT so ordinary RLS decides access,
rather than the function using the service role key for reads/writes it
doesn't need elevated privileges for.

## Deployment

### Local Development

```bash
# Install Supabase CLI
brew install supabase/tap/supabase

# Start local Supabase stack (includes functions emulator)
supabase start

# Deploy a single function to local environment
supabase functions deploy redeem-link-code --no-verify-jwt

# Test the function
curl -X POST http://localhost:54321/functions/v1/redeem-link-code \
  -H "Content-Type: application/json" \
  -d '{"code":"TEST-1234","device_name":"Test Device"}'
```

### Environment Variables

Create `supabase/.env.local`:
```
SUPABASE_URL=https://dyjntcuovsoyhbkxnmih.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<your-service-role-key>
ANTHROPIC_API_KEY=sk-ant-...  # For AI generation function
```

### Production Deployment

```bash
# Deploy all functions to production
supabase functions deploy

# Deploy a single function
supabase functions deploy redeem-link-code

# View logs
supabase functions logs redeem-link-code
```

## Testing

### Unit Tests (Planned)

Each function should have tests covering:
- Valid inputs → success response
- Invalid code → 401 Unauthorized
- Expired code → 401 Unauthorized
- Already-used code → 401 Unauthorized
- Missing environment variables → 500 Internal Error
- Database errors → 500 Internal Error

### Integration Tests (Planned)

Test the full flow:
1. Parent generates code via admin panel
2. Code saved to `device_link_codes`
3. Child redeems code via mobile app
4. Edge Function creates auth user + device record

## Security Checklist

- ✅ `redeem-link-code`: Service role key used only server-side
- ✅ No client secrets exposed
- ✅ Input validation (code format, device_name length)
- ✅ Error messages don't leak internals ("Invalid code" not "Code not found in DB")
- ✅ Rate limiting: Each code can only be used once (DB constraint)
- ✅ Timeout: Codes expire automatically
- ⏳ Future: Rate limit by IP to prevent brute force
